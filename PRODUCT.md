# Product

## Register

brand

## Users

Developers, coding-agent users, and tool builders who want small local automations that can be inspected, versioned, and run outside a specific app. They value plain files, predictable CLIs, small binaries, and workflows that an agent can safely understand.

## Product Purpose

Tickle is a tiny local job daemon for YAML-defined command jobs. It runs cron, interval, manual, and script-gated jobs, records JSONL history, and packages a coding-agent skill so agents can create and maintain jobs without inventing a workflow from scratch.

Success means a visitor understands the shape quickly: YAML in, small checks decide whether work should run, commands execute locally, and history remains easy to audit.

## Brand Personality

Small, practical, precise. Tickle should feel like a pocket tool: light enough to vendor into a skill, solid enough to leave running as a daemon, and plain enough that an agent can reason about it.

## Anti-references

Avoid generic SaaS launch pages, mascot-heavy automation branding, oversized AI-platform promises, blockchain/neon infrastructure styling, and decorative dashboards that obscure the simple file-to-daemon model.

## Design Principles

- Show the loop: config, condition, run, history.
- Make the binary feel small and portable.
- Keep agent support as a practical workflow, not a spectacle.
- Prefer concrete examples over abstract claims.
- Let motion explain cause and effect.

## Accessibility & Inclusion

Use baseline accessible HTML, visible focus states, readable contrast, and reduced-motion support. Animations should support understanding and should not be required to read the page.
